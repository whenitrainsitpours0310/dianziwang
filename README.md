# 点子王

第一次使用请先看 [使用指南 v0.0.1](使用指南-v0.0.1.md)。

私密、轻量的个人创意工作台。记录一句灵感，补充上下文，按需去公开搜索索引里看看别人做到哪一步，并生成可追溯的探索报告与第一版开发需求。

- 中文界面，桌面双栏、移动端可用。
- 不建立账户；灵感与报告默认只保存在当前浏览器的 `localStorage`。
- 外部检索与模型调用全部走服务端 API，密钥不会进入前端或日志。
- 报告中的相关作品必须引用本次检索来源 ID，服务端会拒绝未知来源和模型自造 URL。

## 快速开始

```bash
npm install
cp .env.example .env.local
# 编辑 .env.local，填入 TAVILY_API_KEY、AI_API_KEY、AI_MODEL
npm run dev
```

打开 `http://localhost:3000`。未配置环境变量时，记录、编辑、筛选、导入导出仍可正常使用；探索区域会显示缺少哪些变量，不会填充虚假作品。

## 环境变量

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `TAVILY_API_KEY` | 是 | Tavily Search API 密钥，只在服务端请求头中使用。 |
| `AI_API_KEY` | 是 | OpenAI 兼容 Chat Completions 服务的密钥。 |
| `AI_MODEL` | 是 | 模型名，例如 `deepseek-flash`；请以服务提供方当前支持的名称为准。 |
| `AI_BASE_URL` | 否 | 兼容端点根地址，默认 `https://api.deepseek.com`；也接受完整的 `/chat/completions` 地址。 |

这些变量不要加 `NEXT_PUBLIC_`，不要提交 `.env.local`。`/api/config` 只返回是否已配置、缺失变量名和模型名，不返回密钥或完整地址。

## 探索链路

1. **AI 提取关键词**：服务端调用配置的模型，使用独立 prompt 输出 `{ "keywords": [...] }`；结构校验要求 1-3 个短关键词，拒绝 URL、空值和重复项。关键词阶段失败会明确返回 `AI_FAILED` 或 `AI_INVALID_OUTPUT`，不会退回标题拼接。
2. **生成检索计划**：用真实关键词覆盖所选平台，最多 6 次检索；实际发出的查询逐条保存在报告的 `searchRuns` 和 `queries` 中。
3. **Tavily 公开索引检索**：按 B站、小红书、GitHub、其他网页做有限域搜索，有限并发与超时；只读取索引返回的标题和摘要。
4. **模型结构化分析**：只把来源 ID、标题和索引摘要交给模型，不把用户填写的链接作为证据。只有一个可引用来源时也会分析并引用该来源，同时明确标注覆盖有限。
5. **服务端校验**：结构、引用 ID、用户未读来源、未知 URL 和报告大小都会校验；失败返回明确错误，不生成报告。没有任何检索来源时，模型不得返回相关作品、来源 ID 或 URL。
6. **零结果也给出灵感建议**：至少一次检索成功但没有有效来源时，仍调用模型，只生成基于灵感的延伸方向与第一版建议；相关作品与重合/差异强制为空，报告保持 `empty` 并保留检索元数据，建议明确标注“基于点子本身的建议，尚无检索证据”。全部检索失败仍然失败，不会当作零结果成功。
7. **本地提交**：报告先在内存中完成校验，前端确认 `localStorage` 写入成功后才更新界面并提示"已保存"。

## 数据、隐私与边界

- 记录默认只保存在本机浏览器。主动点击"生成探索报告"时，会把这条灵感的必要内容（原文、标题、补充说明、动机、标签）发送给你配置的模型服务，把检索关键词发送给 Tavily。
- 系统不读取、不抓取用户填写的来源链接；它们只作为"未读取的待核实线索"展示，不能作为相关作品或事实证据。
- 不登录平台、不绕过限制、不把网页材料当指令。搜索来源和模型输出都按不可信数据处理。
- 本地数据损坏时，会先尝试备份到 `dianziwang.v1.corrupt.*`；备份失败则进入写入保护状态，避免空工作区覆盖唯一原始数据。可用浏览器开发者工具导出 `localStorage` 留档。
- 上传/导出仅通过本地文件完成；JSON 导入会校验结构、URL、ID 唯一性、报告归属和来源引用。

## 测试与验收状态

测试包含适配器、API 失败路径、报告引用校验、导入数据校验、持久化边界和 Markdown 生成。夹具测试**不等于**真实联网评估。

当前仓库未提供真实 API 凭据，因此真实 Tavily 检索、真实模型关键词提取与报告生成的端到端验收**尚未完成**。配置凭据后应按以下顺序验收：

1. `npm run typecheck`、`npm test`、`npm run build`。
2. 浏览器走通新增 → 搜索/筛选 → 编辑 → 刷新 → 详情 → 探索 → 删除。
3. 检查报告中的实际检索词、来源链接、失败/空结果提示，确认没有虚假作品或"已联网成功"的夸大文案。

## 已知限制

- 相关作品只来自搜索索引摘要，系统不逐页打开原文，也不声称已阅读或观看。
- 检索词由模型基于灵感提取，可能与实际作品命名不一致；报告会保留这个局限。
- 零有效来源时仍会生成基于灵感的延伸方向与第一版建议，但报告保持 `empty`、相关作品强制为空，并明确标注“基于点子本身的建议，尚无检索证据”；Markdown 会说明没有已核实相关作品。已有历史空报告保持可读、可导出，不会补造作品或建议。
- 只有一个可引用来源时，报告会引用该来源并标注覆盖有限；全部检索失败仍返回 `SEARCH_FAILED`，不会当作零结果成功。
- 搜索范围是公开索引的子集，未覆盖登录后、未被索引或平台限制内容。
- 不提供账户、同步、社区、自动监控、商业评分。
